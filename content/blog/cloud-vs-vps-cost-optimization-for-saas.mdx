## The Hidden Downsides of Serverless for SaaS

While serverless marketing promises "infinite scaling without management," real-world production reveals severe engineering bottlenecks:

1. **Cold Starts:** Serverless functions go to sleep when idle. The next user who triggers a complex API endpoint suffers a 1,500ms to 3,000ms cold boot latency penalty. On a dedicated VPS, Node.js and Go processes are always warm in memory, responding in **sub-25ms**.
2. **Database Connection Exhaustion:** Every serverless function execution spins up a separate connection to your database. Without external pooling proxies, your PostgreSQL instance quickly crashes from connection exhaustion.
3. **Execution Timeout Hard Limits:** Most serverless platforms terminate requests that exceed 10 to 15 seconds. If your SaaS needs to generate a large PDF invoice, run an AI batch script, or process a CSV import, serverless fails without complex decoupled queues.
4. **Bandwidth Egress Tax:** Major cloud providers charge exorbitant rates (up to $0.12/GB) for outbound bandwidth.

## 4 Key Production Standards for Linux VPS Deployments

When [Dazzcode engineers VPS deployments](/services/vps-deployment), we enforce these production standards:

### 1. Multi-Stage Docker Builds
We compile Next.js in standalone mode to create ultra-lightweight Docker images (under 120MB) that boot in milliseconds:

```dockerfile
# Dockerfile snippet for Standalone Next.js
FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static
COPY --from=builder /app/public ./public
EXPOSE 3000
CMD ["node", "server.js"]
```

### 2. Nginx Reverse Proxy with Brotli Compression
Nginx acts as the front door, handling SSL certificates via Let's Encrypt, enforcing HTTP/2 and HTTP/3, and compressing assets with Brotli for faster load times.

### 3. Automated Off-Site Backups
Databases are backed up automatically every 6 hours with cryptographic encryption and uploaded to an external S3 bucket (AWS or Cloudflare R2) to guarantee zero data loss.

### 4. Zero-Downtime Rolling Deployments
Using Docker Compose health checks and Git webhooks (or Coolify / GitHub Actions), new code deployments switch traffic only after new application containers pass health probes.
